# EchoChat Data Ownership Principle

## 目的

本文档明确 EchoChat 项目中各类数据的所有权、控制权和使用边界。

核心原则：**用户数据归用户所有，项目代码归项目权利人所有，品牌资产独立管理。**

## 数据分类

### 1. User Data（用户数据）

**定义**：用户在使用 EchoChat 过程中创建或产生的所有数据。

**包括**：
- 聊天记录和消息历史
- 角色设定（Character / Persona）
- 角色记忆（Memory）
- 关系状态（Relationship）
- Moments（时刻记录）
- 用户配置和偏好设置
- 用户创建的 Worldbook 条目
- 用户导出的数据文件

**所有权**：归创建该数据的**用户**所有。

**控制权**：
- 用户数据默认存储在用户本地设备（localStorage / IndexedDB）
- 用户可以随时导出、删除、修改自己的数据
- EchoChat 不收集、不上传、不分析用户数据
- 用户数据不进入项目仓库

**传输例外**：
- AI API 请求：用户输入的消息内容会通过 API 请求发送给用户配置的 AI Provider
- 用户主动导出或分享：用户自行决定将数据发送到何处
- 详见下方 "External Provider Data"

### 2. Project Code（项目代码）

**定义**：EchoChat 仓库中的所有源代码、配置文件、构建脚本。

**包括**：
- `src/` 目录下的所有代码
- `tests/` 目录下的测试代码
- `config.js`、`sw.js`、`app/index.html`、官网 `index.html` / `landing-v3.html`
- `scripts/` 目录下的脚本

**所有权**：归 **EchoChat Project Contributors** 所有。

**许可证**：PolyForm Noncommercial License 1.0.0（详见 `LICENSE`）。

**用户数据与代码的分离**：
- 代码仓库中**不包含**任何用户数据
- 测试中使用的 fixture 数据是虚构的测试数据，不是真实用户数据

### 3. Project Brand（项目品牌）

**定义**：EchoChat 官方品牌资产。

**包括**：
- EchoChat 名称
- 官方 Logo、Logo Mark、Wordmark
- 官方视觉识别系统
- 官方产品截图中的品牌元素

**所有权**：归 **EchoChat 项目权利人**所有。

**使用规则**：详见 `TRADEMARKS.md`。

**与源码许可证的关系**：品牌资产**不**随源码许可证自动授权。

### 4. Third-party Data（第三方数据）

**定义**：来自第三方服务或资源的数据。

**包括**：
- AI Provider 返回的 AI 生成内容
- 第三方 API 返回的数据
- 第三方字体、图标、图片资源
- 开源库中的示例数据

**所有权**：归各自的**第三方服务提供商或原作者**所有。

**使用规则**：
- 遵循第三方服务的服务条款
- 遵循第三方资源的许可证
- 详见 `THIRD_PARTY_NOTICES.md`

### 5. Plugin Data（插件数据）

**定义**：未来插件系统中，插件创建、存储或访问的数据。

**当前状态**：插件系统尚未实现，本章节为架构原则预留。

**所有权**：
- 插件创建的数据归**插件开发者或用户**所有（取决于插件设计）
- 插件不能默认访问用户的全部数据

**访问边界**：详见 `PLUGIN_POLICY.md`。

### 6. External Provider Data（外部服务提供商数据）

**定义**：用户使用 EchoChat 时，与外部 AI Provider 交互产生的数据传输。

**包括**：
- 用户发送给 AI Provider 的消息内容
- AI Provider 返回的回复内容
- API 调用元数据（如模型名称、token 用量）

**所有权**：
- 用户输入的内容归用户所有
- AI 生成的内容遵循 AI Provider 的服务条款和版权政策

**重要说明**：
- EchoChat 的 "Local-first" 设计指用户数据**默认存储在本地**
- 但 AI API 请求**必然**需要将用户输入发送给第三方 AI Provider
- 因此 "Local-first" **不等于** "所有数据永远不会离开设备"
- 用户应了解并接受：使用 AI 对话功能时，消息内容会传输给 AI Provider

## 数据存储架构

### 当前实现

- **localStorage**：应用状态、聊天记录、角色数据、记忆、关系、Moments
- **Service Worker Cache**：静态资源缓存（HTML/CSS/JS/图片），不包含用户数据
- **无后端服务器**：EchoChat 当前是纯前端应用，没有服务端存储

### 数据隔离

- 用户数据存储在浏览器的 localStorage 中，与其他网站隔离
- 不同浏览器/设备之间的数据不自动同步
- 用户数据不发送到 EchoChat 项目的任何服务器（因为不存在这样的服务器）

## 数据删除

用户可以通过以下方式删除自己的数据：

1. 在应用设置中使用 "清除数据" 功能（如已实现）
2. 在浏览器设置中清除 EchoChat 站点的数据
3. 卸载 PWA 应用

删除后数据不可恢复（除非用户自行备份）。

## 数据导出

用户可以导出自己的数据（如功能已实现）：
- 导出格式由应用定义
- 导出的数据归用户所有，用户可自由处置
- 导出的数据不再受 EchoChat 控制

## 隐私原则

1. **本地优先**：用户数据默认存储在用户设备上
2. **最小传输**：仅在必要时（AI API 请求）传输数据
3. **无收集**：EchoChat 不收集用户行为数据、不使用分析工具、不设置跟踪 Cookie
4. **用户控制**：用户可以随时查看、导出、删除自己的数据
5. **透明**：本文件明确说明数据的所有权和传输方式

## 未来架构调整

如果未来 EchoChat 引入：
- 云端同步
- 多设备同步
- 社区功能
- 插件系统
- 后端服务

将重新评估数据所有权和隐私政策，并更新本文档。

任何涉及用户数据传输的新功能，必须：
- 明确告知用户数据将传输到何处
- 获得用户明确同意
- 提供关闭或退出的选项
- 更新本文档和隐私说明
