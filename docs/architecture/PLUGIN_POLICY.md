# EchoChat Plugin Architecture Policy

**Not a work item.** Plugins are not implemented. Do not start a plugin system unless an explicit work package authorizes it. This file only records the permission boundary if that ever happens.

---

## 目的

本文档定义 EchoChat 未来插件系统的架构原则和权限边界。

**当前状态**：插件系统尚未实现。本文档仅建立架构原则，避免未来插件直接拥有整个 App 的权限。

## 核心原则

```
Core（核心应用）
   ↓
Plugin API（插件接口层，权限控制）
   ↓
Plugin（插件，受限沙箱环境）
```

插件运行在受限环境中，通过明确的 Plugin API 与核心应用交互。
插件**不能**直接访问核心应用的内部状态或全部用户数据。

## 权限模型

未来插件系统必须采用 **Capability / Permission** 模型。

### 插件不能默认获得

插件安装后，**默认不能**访问：

- ❌ 所有聊天记录
- ❌ 用户的 API Key
- ❌ 用户隐私数据（角色设定、记忆、关系等）
- ❌ IndexedDB / localStorage 全部数据
- ❌ 其他插件的数据
- ❌ 核心应用的内部状态
- ❌ 网络请求（无限制）
- ❌ 文件系统访问
- ❌ 用户配置和偏好

### 插件需要显式申请的权限

插件如需访问以下能力，必须在清单（manifest）中声明，并获得用户授权：

| 权限 | 说明 | 授权方式 |
|------|------|----------|
| `chat:read` | 读取当前聊天的消息 | 每次使用时确认 / 安装时授权 |
| `chat:write` | 向当前聊天发送消息 | 每次使用时确认 |
| `character:read` | 读取当前角色设定 | 安装时授权 |
| `memory:read` | 读取当前角色的记忆 | 安装时授权 |
| `memory:write` | 写入当前角色的记忆 | 安装时授权 |
| `network:access` | 发起网络请求 | 安装时授权 + 域名白名单 |
| `storage:plugin` | 访问插件自己的存储区域 | 默认允许（仅限插件自身数据） |
| `ui:panel` | 在 UI 中显示面板 | 安装时授权 |

### 最小权限原则

- 插件只申请实现功能所必需的最小权限
- 用户可以在任何时候撤销插件权限
- 权限被撤销后，插件应能优雅降级或停止运行
- 核心应用应在 UI 中清晰展示每个插件拥有的权限

## 数据隔离

### 插件存储

- 每个插件拥有独立的存储区域
- 插件只能读写自己的存储区域
- 插件不能访问其他插件的存储
- 插件卸载时，其存储区域应被清除

### 用户数据访问

- 插件通过 Plugin API 请求用户数据
- Plugin API 进行权限检查和数据过滤
- 插件只能获得其有权限访问的数据子集
- 敏感操作（如删除聊天记录）需要用户二次确认

### API Key 保护

- 用户的 AI Provider API Key **永远不**暴露给插件
- 插件如需调用 AI API，通过核心应用的代理接口发起
- 核心应用负责注入 API Key，插件看不到 Key 内容

## 插件沙箱

### 运行环境

- 插件代码运行在隔离的沙箱中（如 Web Worker / iframe）
- 插件不能直接访问 DOM（除非通过 `ui:panel` 权限在指定区域渲染）
- 插件不能直接访问 `window`、`document` 等全局对象
- 插件与核心应用通过 postMessage / 结构化消息通信

### 资源限制

- 插件的 CPU / 内存使用应有限制
- 插件的网络请求应有频率限制
- 插件不能阻塞核心应用的主线程
- 插件崩溃不应影响核心应用运行

## 插件清单（Manifest）

每个插件必须包含清单文件，声明：

```json
{
  "name": "插件名称",
  "version": "1.0.0",
  "description": "插件功能描述",
  "author": "作者",
  "permissions": ["chat:read", "ui:panel"],
  "entry": "index.js",
  "apiVersion": "1.0"
}
```

核心应用在安装插件时：
1. 解析清单
2. 展示插件申请的权限
3. 获得用户确认
4. 安装插件

## 插件审核

当前阶段不开放第三方插件市场。未来如开放：

- 插件需经过基本安全审核
- 恶意插件（窃取数据、越权访问）应被禁止
- 社区可举报可疑插件
- 插件来源应可验证（签名 / 哈希）

## 与源码许可证的关系

- 插件是独立作品，其许可证由插件开发者决定
- 插件不自动成为 EchoChat 源码的一部分
- 插件使用 EchoChat Plugin API 不意味着插件必须采用与 EchoChat 相同的许可证
- 但插件不得违反 EchoChat 的商标政策（详见 `TRADEMARKS.md`）

## 当前不做的事

本文档**不**要求：
- 现在实现插件系统
- 现在实现 Plugin API
- 现在实现插件沙箱
- 现在开放插件市场

本文档只建立原则，确保未来实现插件系统时，不会出现"插件默认拥有整个 App 权限"的设计缺陷。

## 未来实现检查清单

未来实现插件系统时，必须验证：

- [ ] 插件不能读取其他插件的数据
- [ ] 插件不能读取用户的 API Key
- [ ] 插件不能在未授权时访问聊天记录
- [ ] 插件权限可以被用户随时撤销
- [ ] 插件崩溃不影响核心应用
- [ ] 插件网络请求有限制和日志
- [ ] 插件存储在卸载时被清除
- [ ] 敏感操作需要用户二次确认
